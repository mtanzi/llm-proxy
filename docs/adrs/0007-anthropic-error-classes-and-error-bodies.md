# ADR 0007: Error classes and protocol-correct error bodies

Status: Accepted

Date: 2026-10-21

## Context

Claude Code's retry logic matches on the upstream's error wording, so error bodies from the upstream must never be wrapped. The proxy still generates some errors itself (bad key, oversize body, upstream unreachable), and those must look like Anthropic errors so the client handles them correctly (gap review R3). Call records need a small controlled vocabulary for what went wrong.

## Decision

- Errors generated by the proxy use the Anthropic error body shape, with a stable `type` per error class.
- Errors from the upstream (4xx, 5xx) reach the client unchanged, with `x-request-id` added.
- `error_class` is a small controlled vocabulary: `rate_limited`, `upstream_5xx`, `timeout`, `auth`, `client_abort`, `invalid_request`, `internal`. The provider's own error `type` (for example `overloaded_error`) is stored separately as `error_type`.
- The provider's error message text is not kept (see Proposed ADR 0044 for the alternative).
- `retry-after` is forwarded from the upstream; when the proxy generates a rate-like error it sends integer seconds.
- The error builders live in `family/anthropic` (pure functions); `proxy` calls them.

## Consequences

- Clients keep their own retry behaviour because upstream errors are untouched.
- The vocabulary is closed: a new class is a deliberate change with a test.
- Auth failures (ADR 0008) and size failures (ADR 0006) use the same builders.

## Work required

- Define the `error_class` constants in `core` and the mapping from HTTP status and failure kind to a class.
- Implement the error body builders in `family/anthropic` for: missing or invalid key (401), disabled key (401), oversize body (413), malformed request (400), upstream unreachable or timeout (502/504), internal error (500). Each has a fixed `type`.
- Golden-test the bodies against the documented Anthropic error shape.
- Test that the mapping assigns exactly one class per outcome, including client abort and idle-timeout.
- Document the error `type` per class in the repository docs.
